# v0.2.0 Inference Mechanics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add supported sampling controls, measured per-request timings (TTFT, TPOT, decode TPS, total), a derived KV-cache size estimate, and documentation/notebook that separate conceptual, derived and measured values.

**Architecture:** Extend the existing domain value objects (`GenerationConfig`, `GenerationResult`) and the `ModelExecutionPort`; keep all timing capture and sampling mapping inside `TransformersInferenceAdapter`; compute metrics with pure domain functions fed by raw `perf_counter_ns` stamps. No new layers, no HTTP changes (HTTP generate/stream is v0.3.0).

**Tech Stack:** Python 3.12, uv, pytest, ruff, import-linter, transformers/torch (optional `ml` extra).

**Spec:** `docs/MASTER_IMPLEMENTATION_GUIDE.md` §18 "v0.2.0 — Inference mechanics" and `CLAUDE.md` §12 (metric definitions), §10 (Clean Architecture), §13 (runtime safety).

## Global Constraints

- Exit criterion (guide §18): "metric boundaries documented; conceptual values never masquerade as runtime measurements."
- Clock: `time.perf_counter_ns()` only (CLAUDE.md §12).
- `TTFT = first_output_token_time - request_start`; `TPOT = (last_token_time - first_token_time) / (output_tokens - 1)` when `output_tokens > 1`; `Decode TPS = (output_tokens - 1) / (last_token_time - first_token_time)` when denominator > 0. One output token → TPOT and decode TPS are `None`, never 0.
- Documented request start: moment `generate()` has acquired the adapter lock; it **includes** tokenization and host-to-device transfer, **excludes** lock/queue wait. This boundary is written in code docstring and `docs/inference-mechanics.md`.
- Raw per-token timestamps are preserved on the result; no percentiles or benchmarks in this release (v2.0.0).
- No fabricated metrics: docs and README may show only values from a run recorded in `docs/v0.2.0-verification.md`, labelled with hardware and "single run, not a benchmark".
- Never log prompt/generated text; log allowlist may gain only numeric metric fields.
- `trust_remote_code=False`; unsupported controls are rejected with `InvalidGenerationConfigError`, never silently ignored.
- Dependency rule: domain/application import no frameworks (`uv run lint-imports` must stay green, 2 contracts kept).
- Backward compatible: `GenerationConfig(max_new_tokens=n)` and `GenerationResult(text, prompt_tokens, output_tokens)` keep working.
- Out of scope (deferred, ledger as such): stop sequences (v1.2.x), HTTP endpoints/SSE (v0.3.0), percentiles/benchmark protocol (v2.0.0), chat templates.
- Branch: `feat/v0.2-inference-mechanics` from `main`; one PR. Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Before each commit follow CLAUDE.md pre-commit checks (staged diff review, gitleaks).
- Working directory for commands: `backend/`.

## Review Focus

- `temperature=0` combined with `top_k`/`top_p`: must raise, not silently ignore (Task 1).
- Same `seed` + same prompt + same config twice on the real model → identical text; a seeded run must not change the sampling state of later unseeded runs in a way tests can detect as shared global state (Task 4).
- Output of exactly 1 token (`max_new_tokens=1`) and 0 tokens (immediate EOS): TPOT/TPS `None`, TTFT `None` for 0 tokens, no division by zero (Tasks 2, 4).
- Timestamps monotonic non-decreasing and `len(token_timestamps) == output_tokens` on the real adapter (Task 4).
- Timing capture or streamer failure must surface as `InferenceFailedError`, never hang or crash the process (Task 4).
- Logs and CLI metrics output contain numbers only, never prompt/response text (Task 6).
