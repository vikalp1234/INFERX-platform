# v0.3.0 API and Streaming Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose tokenize, generate and SSE-streamed generate over typed HTTP endpoints with request IDs, a stable error envelope, input/output limits and bounded, cancellable execution.

**Architecture:** Add a streaming method to `ModelExecutionPort` (sync iterator + cancel token); add an application-level `RequestGate` (bounded concurrency + bounded waiting) and `StreamGeneration`/`GetModelStatus` use cases; keep every FastAPI/pydantic type in `adapters/inbound/http`; wire in the existing composition root. No new third-party dependencies (SSE is hand-formatted).

**Tech Stack:** Python 3.12, FastAPI, pydantic v2, uvicorn, pytest, httpx (already a dev dependency), import-linter.

**Spec:** `docs/MASTER_IMPLEMENTATION_GUIDE.md` §18 "v0.3.0 — API and streaming" (deliver: typed schemas, generate/tokenize endpoints, SSE, request IDs, terminal events, input/output limits, controlled execution, integration tests; exit: client receives stream and terminal event, errors stable, concurrency bounded) and `CLAUDE.md` §10, §11, §13, §14.

## Global Constraints

- Dependency rule: pydantic/FastAPI/starlette only in `app/adapters/inbound/http` and `app/bootstrap`; `uv run lint-imports` stays green (2 contracts kept). Adapters must not import `app.bootstrap`: routes read dependencies from `app.state.api_deps` (a small dataclass defined in `adapters/inbound/http/dependencies.py`), which `bootstrap/app_factory.py` populates.
- Routes: `GET /health` (unchanged), `GET /v1/model`, `POST /v1/tokenize`, `POST /v1/generate`, `POST /v1/generate/stream` (SSE, `text/event-stream`). No model-load endpoint and no model ID in any request body (CLAUDE.md §13); the model is the configured, pinned one, optionally loaded at startup via `INFERX_AUTOLOAD_MODEL` (default `false`).
- Request bodies reject unknown fields (`extra="forbid"`); `prompt` max length = `INFERX_MAX_PROMPT_CHARS`; `max_new_tokens` ≤ `INFERX_MAX_NEW_TOKENS`; request body larger than `INFERX_MAX_BODY_BYTES` (default `65536`) → 413.
- Request ID: every response carries `X-Request-ID`. An incoming `X-Request-ID` is honored only if it matches `^[A-Za-z0-9._-]{1,64}$`; otherwise a new `uuid4().hex` is generated. Logs gain `request_id` (allowlisted). No prompt or generated text in logs, error bodies or validation messages.
- Error envelope, always: `{"error": {"code": str, "message": str, "request_id": str}}`. Codes/status: `invalid_request` 422 (schema or domain validation), `payload_too_large` 413, `model_not_loaded` 409, `overloaded` 429 (with `Retry-After`), `inference_failed` 500, `internal_error` 500. Messages are fixed strings or domain messages that never echo user input.
- SSE contract: events `token` (`{"index": int, "text": str}`) then exactly ONE terminal event: `done` (`{"request_id", "finish_reason", "prompt_tokens", "output_tokens", "metrics"}` where `metrics` is `RunMetrics.to_dict()`) or `error` (the error envelope body). Nothing is sent after a terminal event. Stream text deltas never contain U+FFFD produced by splitting a multi-byte character.
- `finish_reason` ∈ {`stop` (EOS), `length` (hit `max_new_tokens`), `cancelled`}.
- Concurrency: `INFERX_MAX_CONCURRENT_REQUESTS` (default `1`), `INFERX_MAX_WAITING_REQUESTS` (default `4`), `INFERX_QUEUE_WAIT_TIMEOUT_S` (default `30`). Request lifecycle states documented in the graph: `queued → running → completed | failed | cancelled`, plus `rejected` (never entered the queue). A client disconnect cancels generation and frees the slot.
- Trust boundary: the API has no authentication in v0.3.0 (identity arrives in v3.3/v4.0). Docs state it is for local or trusted-network use, and default bind stays loopback. Do not describe it as production-ready.
- Latency/throughput numbers appear only in dated verification records, labelled single run.
- Branch `feat/v0.3-api-streaming` from `main`; one PR; commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; CLAUDE.md pre-commit checks apply. Commands run from `backend/` unless stated.
- Out of scope (ledger as deferred): authentication/rate limiting per user, model load/unload endpoints (v1.0), persistence/SQLite (v1.0), cancellation endpoint by request ID (v1.1.x), chat templates, stop sequences (v1.2.x), percentiles (v2.0.0).

## Review Focus

- Client disconnect mid-stream (and before the first byte is read) must stop generation and release the slot; a following request succeeds (Task 6, real-uvicorn integration test).
- An error raised after the first `token` event yields exactly one `error` terminal event and no `done` (Task 6).
- Pydantic validation errors, oversized prompt and malformed JSON must not echo the prompt or raw body (Task 4).
- Overload: with all slots busy and the waiting room full, the next request gets 429 + `Retry-After` immediately, not a hang (Tasks 3, 5).
- Spoofed/invalid `X-Request-ID` (newline, 65+ chars, empty) is replaced, never reflected or logged raw (Task 4).
- Streamed text with multi-byte characters and emoji never yields U+FFFD mid-character (Task 2).
- Model not loaded → 409 with envelope on all three POST routes; `/health` stays 200 (Task 5).

**Interfaces:**

- Behavior: validation, model-loaded check and `gate.check_capacity()` happen BEFORE the response starts, so those failures are normal HTTP errors (422/409/429). The async generator wraps the sync iterator, polls `request.is_disconnected()` between events, sets the `threading.Event` cancel token on disconnect or cancellation, and closes the sync generator in `finally` (via `run_in_threadpool`) so the slot is always released.
