## Real-model tests

`uv run pytest -m model -q` → **26 passed** (adds streaming/cancel/finish-reason/multi-byte tests to the v0.2.0 contract).

## HTTP run (curl, prompt: "The capital of France is")

- `GET /health` → `{"status":"ok"}`; `GET /v1/model` → loaded `true` with the pinned revision.
- `POST /v1/tokenize` → 5 tokens, `request_id` equal to the `X-Request-ID` header.
- `POST /v1/generate` (12 tokens) → 200, `finish_reason` `length`, metrics labelled `measured` / `derived_from_model_config`.
- `POST /v1/generate/stream` (8 tokens) → 8 `token` events with indices 0–7, then one `done` event.
- Unknown field `model` → 422 `invalid_request` (message names the field only). Greedy with `top_k` → 422. 70 KB body → 413 `payload_too_large`. Invalid `X-Request-ID` (`bad id;x`) → replaced by a generated 32-hex ID.
- Overload (waiting room 0): while a 200-token stream ran, `POST /v1/generate` and `POST /v1/generate/stream` each returned 429 with `Retry-After: 1` (the stream route as JSON, not SSE). The first stream still finished with 200 `token` events and one `done`.
- Mid-stream abort (`curl -N -m 1`, 37 token events received): in three repeated measurements the slot was free again after roughly 30–60 ms. Release latency is not tightly bounded, though: in an earlier run two requests sent right after an abort were refused with 429 (no waiting room) before a third succeeded, because the disconnect poll interval is 0.1 s and the worker stops at the next token.
- Seeded sampling (`temperature 0.8`, `seed 7`, 12 tokens): identical text on two runs ( " Paris, a city known for its stunning architecture and rich history").
- Server log contained no prompt text (searched for the prompt strings: 0 matches).

## Automated

`uv run pytest -q`: 200 passed, 1 skipped (a header the HTTP client refuses to send), 26 deselected; ruff and `lint-imports` clean. The uvicorn integration tests were run 5 times in a row, all green, and the disconnect tests were shown to fail when cancellation/cleanup was removed.

## Not verified

- Behavior under sustained concurrent load, long streams, or other hardware.
- Browser `EventSource` clients and reverse proxies.
- CUDA/other accelerators.
- Multi-process deployments (capacity bounds are per process).
- A client that disconnects while still waiting for a slot: the wait ends only at the queue timeout (documented limitation).
