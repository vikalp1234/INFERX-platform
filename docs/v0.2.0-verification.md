# v0.2.0 verification evidence

Purpose: show that sampling controls, per-token timings and the derived KV estimate work against the pinned model, and record the metric boundaries in use. **These are single runs, not benchmarks**; the first generation in a process includes one-time warm-up cost, so its TTFT is not representative.

## Real-model contract tests

Command: `cd backend && uv sync --frozen --extra ml && uv run pytest -m model -q`

Result: **18 passed, 115 deselected**. Covers: one timestamp per output token, monotonic stamps, one-token output gives `null` TPOT and decode TPS, same seed gives same text, greedy ignores seed, runtime failure becomes `InferenceFailedError` and the adapter recovers, a seeded run restores the global torch RNG state (the test was shown to fail when the restore was removed), architecture fields positive.

## CLI runs (prompt: "The capital of France is")

Greedy, 16 tokens, `--metrics` (first generation in the process, includes warm-up): `prompt_tokens` 5, `output_tokens` 16, `ttft_ms` ≈ 1662, `tpot_ms` ≈ 34.0, `decode_tps` ≈ 29.4, `total_ms` ≈ 2174, KV estimate 860,160 bytes (21 tokens × 40,960 bytes/token, **derived**).

One token (`--max-new-tokens 1`): `ttft_ms` ≈ 309, `tpot_ms` null, `decode_tps` null, KV estimate 245,760 bytes (6 tokens).

Seeded sampling (`--temperature 0.8 --seed 7`, 16 tokens), run twice in separate processes: identical text both times.

stdout carried only the prompt-token line and generated text; the metrics JSON went to stderr with a provenance label on every value.

## Metric boundaries in use

See [inference-mechanics.md](inference-mechanics.md): request start is taken after the adapter lock is acquired, includes tokenization and device transfer, excludes lock wait; TTFT includes prefill plus first-token selection.

## CI-level checks (no PyTorch)

`uv run pytest -q`, `ruff check`, `ruff format --check` and `lint-imports` (2 contracts kept) were run on the branch; exact counts are in the PR checks.

## Not verified

- CUDA or other accelerators (seed isolation for CUDA RNG is untested).
- Behavior under concurrent requests (the adapter serializes with a lock; no load test).
- Any cross-hardware or cross-version reproducibility of seeded output.
